# 장어 가격 추적기

거래처 몰의 특정 상품 가격과 시장 시세(양념민물장어, 냉동민물장어필렛)를
매일 자동으로 수집해 이력을 쌓는 도구입니다. GitHub Actions가 **매일 07:30 KST**에
실행하며, 결과는 이 폴더의 CSV 파일에 커밋됩니다. 가격 변동이 감지되면
저장소에 이슈가 자동 생성됩니다(저장소 Watch 시 메일 알림).

## 구성

| 파일 | 역할 |

| `import_price.py` | (대기) 관세청 공공 API 수집기 — 게이트웨이가 해외 IP를 차단해 국내 실행 시에만 유효 |

## 온라인 소매 시세 — 패널 방식

네이버가 쇼핑 검색 API를 2026-07-31 종료하여 **키워드로 상위 100개를 긁는
방식은 더 이상 불가능**합니다. 쿠팡 파트너스 검색 API도 시간당 10회·회당
10건 제한이라 시세 조사용으로는 못 씁니다. 등록하신 `NAVER_CLIENT_ID`/
`NAVER_CLIENT_SECRET`는 사용되지 않으며 삭제하셔도 됩니다.

대신 **대표 판매글을 고정해두고 매일 그것만 관측하는 패널 방식**을 씁니다.
소비자물가지수(CPI)가 대표 품목 바스켓을 고정해 추적하는 것과 같은 원리입니다.
매일 다른 상위 100개를 보면 순위 변동이 가격 변동으로 오인되지만, 같은
판매글을 계속 보면 진짜 가격 변화만 잡힙니다.

전체 설계는 [온라인 소매가 추적 시스템 설계](../reports/online-price-tracking-design.md)를
참고하세요.

### 패널 만들기 (최초 1회, 반나절)

**이 단계가 전체 품질의 8할을 결정합니다.** 목적이 시장가격 조사이므로
패널이 곧 표본이고, 여기서 고른 오퍼가 곧 시세의 정의가 됩니다.

**① 표집 프레임 수집**

네이버쇼핑·쿠팡에서 품목별 검색어로 상위 50~100건을 한 번 훑고 상품 URL을
모읍니다. 붕장어·바다장어·진액·소스류는 제외합니다.

검색어 예: `민물장어 필렛`, `국내산 장어 필렛`, `양념 민물장어`, `손질 민물장어`

**② 등록**

```bash
python3 tracker/retail_panel.py --add \
  "https://smartstore.naver.com/.../products/..." \
  "https://www.coupang.com/vp/products/..."
```

제목을 읽어 형태·원산지·보관·중량·미수를 자동으로 채우고 품목까지 배정합니다.
판정이 애매하면 `match_status=pending`으로 두므로, 자동으로 틀린 값이
들어가지는 않습니다.

**③ 검토 — 사람이 하는 유일한 작업**

`panel_offers.csv`를 열어 `pending` 행을 확인합니다. 확인할 칸은 셋뿐입니다.

| 칸 | 할 일 |
|---|---|
| `total_g` | 제목에서 못 읽었으면 실제 총 중량(g)을 적습니다. **옵션이 여러 개면 하나를 고정**하세요 |
| `shipping_fee_krw` | 배송비. 무료면 `0`, 모르면 비워 둡니다(0과 빈칸은 다르게 취급됩니다) |
| `item_id` | 비어 있으면 `panel_items.csv`에서 골라 적습니다 |

다 채웠으면 `match_status`를 `confirmed`로 바꿉니다. **한 번 confirmed면 이후
자동 로직은 그 행을 건드리지 않습니다.**

**④ 분위 배정**

수집을 1회 돌린 뒤 실행하면 품목별 가격 3분위(lo/mid/hi)를 자동 배정합니다.

```bash
python3 tracker/retail_panel.py            # 1회 수집
python3 tracker/retail_panel.py --assign-terciles
```

**⑤ 현황 확인**

```bash
python3 tracker/retail_panel.py --status
```

품목당 오퍼가 **최소 9개**(3분위 × 3개)는 되어야 합니다. 권장은 15개,
전체 60개입니다. 부족하면 지표 신뢰도가 낮다고 리포트에 표시됩니다.

### 왜 상위 노출만 담으면 안 되는가

네이버·쿠팡의 상위 노출은 광고비·판매량의 결과이지 가격 대표성이 아닙니다.
상위만 담으면 유입용 저가 미끼상품 때문에 **시세가 실제보다 낮게** 나오거나,
대형 판매자만 담으면 **브랜드 프리미엄이 과대 반영**됩니다.

문제는 이 편향이 **조용하다**는 점입니다. 숫자는 매일 멀쩡히 나오고 틀렸다는
신호가 없습니다. 그래서 가격 3분위에서 균등하게 뽑고, 어떤 검색어로 몇 건
중에서 골랐는지를 `panel_changelog.csv`에 남깁니다.

## 일일 리포트 발송 (슬랙 또는 메일)

매일 실행이 끝나면 세 층의 최신 상태와 **변동 유무를 명시한 리포트**가
발송됩니다 (변동이 없어도 "변동 없음"으로 발송). 슬랙과 메일 중 시크릿이
등록된 채널로 발송되며, 둘 다 등록하면 둘 다 발송됩니다.

**슬랙 (권장, 2분)**

1. https://api.slack.com/apps → Create New App → From scratch → 워크스페이스 선택
2. 왼쪽 메뉴 **Incoming Webhooks** → 활성화(On) → **Add New Webhook to Workspace**
   → 리포트를 받을 채널 선택 → 생성된 `https://hooks.slack.com/services/...` URL 복사
3. GitHub 저장소 → Settings → Secrets and variables → Actions →
   Name: `SLACK_WEBHOOK_URL`, Secret: (복사한 URL)

**메일 (`info@khglobaltrade.com` 수신)**

- `MAIL_USERNAME`: 발신용 이메일 주소 (예: Gmail 주소)
- `MAIL_PASSWORD`: 해당 계정의 SMTP 비밀번호
  (Gmail은 구글 계정 → 보안 → 2단계 인증 → 앱 비밀번호에서 생성:
  https://myaccount.google.com/apppasswords)
- (선택) 회사 메일서버를 쓰려면 `MAIL_SERVER`, `MAIL_PORT` 추가
  (미지정 시 smtp.gmail.com:465)

수신 주소를 바꾸려면 `.github/workflows/price-tracker.yml`의 `to:` 값을
수정하면 됩니다. 여러 명은 쉼표로 구분합니다.

## 중국산 수입실적 (키 불필요)

KATI(농수산식품수출지원정보)의 월별품목별 실적을 통해 관세청 통관 기준
중국산 장어 수입 중량(kg)·금액($, CIF)을 매일 수집합니다. 뱀장어(활/기타),
실장어, 조제 장어(1604.17) 등 장어 전 품목이 대상이며 바다장어류는
제외합니다. 첫 실행에서 18개월 소급, 이후 최근 3개월을 갱신합니다(전월
확정치는 통상 익월 중순 반영). 등록하신 `DATA_GO_KR_KEY`는 현재 사용되지
않습니다 — 관세청 API 게이트웨이가 해외 IP를 차단해 GitHub 러너에서 접근
불가함을 확인했고, 같은 통관 데이터를 KATI로 대체했습니다.

## 소매 시세 산출 방식

- 비교 기준은 **배송비 포함 원/kg** 하나입니다. 표시가격끼리는 비교하지 않습니다.
- 대표값은 **중앙값의 7일 이동평균**입니다. 최저가는 기록하되 헤드라인에서는
  뺐습니다 — 자사 판매가 없어 대응할 행동이 없으므로 한 판매자의 일시 할인은
  시장 신호가 아니기 때문입니다.
- 분산은 `p75 ÷ p25`로 봅니다. `max ÷ min`은 양 극단 하나씩에 휘둘립니다.
- 이상치는 **제외하되 기록은 남깁니다.** 절대 밴드(300g~5kg, 5천~100만원)와
  직전 30일 중앙값의 0.4~2.5배 밴드로 거릅니다.
- `offer_snapshots.csv`는 **추가 전용**입니다. `item_daily.csv`·`retail_cross.csv`는
  전량 재생성되는 파생물이라, 나중에 매칭이나 규칙을 고쳐도 과거까지 한 번에
  다시 계산됩니다.

### 마진 구조 (리포트 6번 항목)

소매가가 도매·수입 시계열과 엮이면서 **수입 → 도매 → 소매** 전 구간이
한 화면에 들어옵니다.

| 지표 | 정의 |
|---|---|
| 원산지 가격차 | 국내산 필렛 ÷ 중국산 필렛 중앙값 |
| CIF 원가 대비 배수 | 소매 중앙값 ÷ (수입 CIF USD/kg × 환율) |
| 소매 ÷ 도매 | 소매 중앙값 ÷ 활 뱀장어 경매가 (수율 미보정) |

품목은 관세청 HS 코드에 대응돼 있습니다 — 필렛 `0304690000`,
양념구이 `1604171000`/`1604179000`, 통장어 `0303290000` (모두 중국산 기준).

**관세·통관비는 아직 반영되지 않습니다.** 관세율은 HS 코드·협정·연도에 따라
달라 임의값을 넣으면 지표가 통째로 무의미해지므로, 확정될 때까지 CIF 기준으로만
산출하고 리포트에도 그렇게 표시합니다. 확정되면 `retail_config.py`의
`LANDED_COST`에서 `enabled`를 `True`로 바꾸고 값을 채우면 됩니다.

환율은 관세율과 달리 객관적인 값이라 `retail_fx.py`가 매일 자동으로 받아
`fx_history.csv`에 쌓습니다. 관세청 고시환율로 고정하고 싶으면
`retail_config.USDKRW_OVERRIDE`에 숫자를 넣으면 됩니다.

### 알림

즉시 대응할 일이 없는 시장조사 용도라, 알림은 **추세 전환**과 **시스템 고장**
두 가지로 좁혔습니다.

| 이벤트 | 조건 | 등급 |
|---|---|---|
| 수집 이상 | 파싱 실패율 20% 초과 | **최우선** |
| 표본 붕괴 | 분위별 관측 2건 미만 | **높음** |
| 추세 전환 | 7일 이동평균 전주 대비 ±5% | 보통 |
| 원산지 가격차 이동 | 전월 대비 ±10% | 보통 |
| 검토 필요 | pending 오퍼 5건 이상 | 낮음 |

수집 이상을 최우선에 둔 이유는, 가격 알림은 안 와도 손해가 제한적이지만
**수집이 조용히 죽으면 그동안 쌓은 숫자가 전부 못 쓰게 되기** 때문입니다.

## 항목 추가

- **거래처 상품**: `products.csv`에 `라벨,URL` 한 줄 추가
  (라벨은 이력 파일의 키이므로 한 번 정하면 유지)
- **소매 패널 오퍼**: `python3 tracker/retail_panel.py --add <URL>` (위 '패널 만들기' 참고)
- **추적 품목**: `panel_items.csv`에 행 추가. `origin`에 `*`를 넣으면 원산지 무관입니다.
  품목을 늘리면 품목당 오퍼도 최소 9개씩 필요해집니다.

## 주의사항

- **스케줄 실행은 저장소 기본 브랜치의 워크플로우만 작동합니다.**
- 가격이 로그인 후에만 보이는 몰은 시크릿 `FOODEN_COOKIE`에 세션 쿠키를
  등록하면 수집됩니다 (만료 시 갱신 필요).
- 수집은 하루 1회, 등록된 페이지/공식 API만 사용합니다. robots.txt가
  금지하는 경로는 건너뜁니다.
- 과거(추적 시작 이전) 가격은 소급할 수 없습니다. 이력은 시작일부터 쌓입니다.
- **네이버·쿠팡은 봇 탐지가 강합니다.** 차단되면 우회하지 않고 해당 오퍼를
  `blocked`로 표시합니다. 특정 분위의 오퍼만 계속 차단되면 표본이 조용히
  편향되므로, 그 분위를 다른 오퍼로 보충해야 합니다.
- 패널을 바꾸면 그날 시세가 점프한 것처럼 보이는데, 실제 가격 변동이 아니라
  관측 대상이 바뀐 것입니다. `panel_changelog.csv`의 변경일을 감안해 읽으세요.
- 소매 수집은 하루 1회, 오퍼 30~80건으로 두 포털 어느 쪽에도 부담을 주지 않는
  수준입니다. robots.txt가 금지하는 경로는 건너뜁니다.
- 원물 도매시세는 시세판(sisepan.com)의 장어 품목 페이지와 내수면어류 분류
  페이지 5곳(활/냉동/신선)을 하루 1회 읽어, 민물장어 계열(뱀장어·수입장어)
  경매만 골라 누적합니다. 시세판은 전국 32개 공영도매시장 경매를 집계하는데,
  **민물장어는 산지 직거래 중심이라 실제로 경매가 서는 시장이 안산·안양·
  대전오정·대전노은 등 소수입니다** — 잡히는 시장 수가 적은 것은 수집 누락이
  아니라 유통 구조 특성이며, 새 시장에 경매가 생기면 자동으로 포함됩니다.
  페이지 구조가 바뀌면 실행 로그에 경고가 남습니다.
- 산지가격 보강 후보: KMI 수산업관측센터(foc.re.kr)의 뱀장어 관측(월간),
  fishdata.kmi.re.kr OPEN-API(키 발급 필요). 필요 시 추가 연동 가능합니다.
